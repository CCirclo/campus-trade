# 系统架构

学校隔离键为 `(school_id, campus_id)`。列表、关键词/混合搜索和推荐均过滤两个字段，推荐游标上下文也包含二者。已登录请求完全采用服务端会话用户的范围；匿名请求只能使用公开目录中的合法组合。商品保存发布时范围，用户切换校区不会改变历史商品归属。

学校元数据持久化在 `schools`、`campuses`、`school_email_domains`，负责人关系在 `school_admins`。固定总管理员邮箱 `2025202211@ruc.edu.cn` 拥有全平台范围；其他 admin 的范围由负责人关系决定（兼容旧 admin 时回退到账号学校）。后端在每个 Admin 查询和变更端点附加学校授权条件，前端隐藏不属于其权限的数据不是安全边界。

商品详情同样执行校区授权：主人始终可访问自己的商品；其他用户只有在 `(school_id,campus_id)` 与商品发布快照完全一致时才能查看或互动。自己的主页和“我的发布”返回所有校区并由前端分组，其他人主页只返回其当前校区的在售商品。

## 组件与边界

```text
浏览器 / React 19
        │ HTTPS /campus-trade/
        ▼
      nginx
        │ 127.0.0.1:8787
        ▼
 Node.js 22 + Express 5 ──── MySQL 8
        │                       ├─ 业务数据
        │                       ├─ 行为事件
        │                       └─ 商品向量/任务状态
        ├─ 腾讯云 COS（图片）
        ├─ SMTP（验证码/通知）
        └─ 127.0.0.1:8080
              TEI + BAAI/bge-small-zh-v1.5
```

- nginx 是唯一公网入口；API 和 Embedding 只监听回环地址。
- Express 负责身份、学校边界、参数校验、检索/推荐编排和降级。
- MySQL 是业务与队列状态的唯一持久化真相源；Embedding 等待任务不依赖进程内存。
- TEI 是可选本地依赖；它不可用时业务自动回退到关键词/最新发布。

## 商品向量生命周期

1. 发布或编辑商品后，API 将标题、分类、成色和描述规范化并计算内容哈希。
2. `item_embeddings` 通过 `item_id + model_version` 幂等写入 `pending`。内容和模型版本未变时保留 `ready` 向量。
3. API 响应只等待入队落库，不等待推理。
4. 后台 worker 每次只 claim 一件商品，一次只向模型发送一条文本，成功后写入 L2 归一化的 512 维向量。
5. 失败任务最多重试 3 次，指数退避；异常退出遗留的 `processing` 状态在启动时恢复。

## 搜索优先级与降级

1. 始终先执行关键词检索。
2. 关键词结果不少于 `HYBRID_SPARSE_RESULT_THRESHOLD` 时，如果模型正忙则立即返回关键词结果。
3. 结果过少时，Query Embedding 可进入有界高优先级队列；它不中断已开始的商品任务，但优先于未开始的商品任务。
4. 排队满、超时、服务错误或维度不符时只降级本次搜索。
5. 向量召回最多扫描 `EMBEDDING_VECTOR_SCAN_LIMIT`，Query 缓存最多 64 条，防止随数据量无界增长。

## 推荐数据流

- 前端批量上报搜索、曝光和点击；登录态转化由服务端信任边界补充用户 ID。
- 原始搜索词不落库，仅保存 HMAC-SHA256 指纹。缺失专用密钥时，首次生产启动生成独立 256 位随机值到 `runtime_secrets`。
- 召回强制同校、在售、非本人商品；排序结合兴趣、新鲜度、平滑热度、价格和探索。
- 灰度未命中或全局关闭时使用 `latest-v1`，不需要数据库回滚。

## 关键不变量

- 不跨学校召回，不推荐本人或非在售商品。
- 用户文本只做参数化 SQL，不插值到 SQL 结构。
- 上传成功不以 Embedding 生成成功为条件。
- 同一时刻只有一个模型 HTTP 请求，已开始任务不被抢占。
- 任何推荐/Embedding 故障都不得影响发布、商品详情和关键词搜索。
